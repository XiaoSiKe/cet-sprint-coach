# 听力、阅读、写译与词汇训练

## 通用流程

用 `drill --section ...` 取一题并显示来源与题型。已有到期题 ID 时直接用 `drill --item-id ID`；需要查看排期时用 `review` 或 `review --through YYYY-MM-DD`。答案和听力脚本始终由引擎隐藏到学生作答后。原创题先按[出题与核验协议](item-authoring.md)检查。学生提交答案后才用 `attempt --response ...`；客观题有已核验单字母选项时引擎核对，其他情况由教练给出 `correct/partial/wrong/unverified` 和判断依据。没有可信答案时反馈推理过程。训练记录区分来源、用时与错因。相同机制持续出现时沿用错因标签，例如“把例子当主旨”。`same_error_streak_distinct_items` 表示同题型同判断依据的不同题上连续出现的同一错误。达到三次，先对比原文正反例，等学生说出判断标准后，再用 `drill --focus --fresh` 取新题复测。方法选择见[学习科学](learning-science.md)。

## 作答模式

首次看题、无提示作答用默认模式。已经读过脚本、看过解析、接受提示、暂停重听，或正在跟着范例改写时，用 `attempt --assisted` 记录练习。辅助作答保留反馈，同题后续作答按复习观察。要验证迁移，换成同题型的新题再独立作答。

## 听力

四级区分短篇新闻、长对话、篇章；六级区分长对话、篇章、讲话/报道/讲座。先展示音频和题干，按已约定的播放和计时条件作答。可播放文件只证明练习可用，学生实际听过才有听力证据。提交以后，`attempt` 返回已有脚本与可用答案。让学生对照一个具体片段，分辨是声音识别、词义转折、同义改写，还是被干扰信息带偏。下一次用新的音频片段验证同一机制。错因至少能分辨没听出声音、听懂词却没抓逻辑、同义替换、干扰信息和时间压力。Agent 可在本机有可用 TTS 时制作原创辅助音频，但必须标明“合成音频，非官方考试材料”；生成文本与答案在作答前隐藏。无音频只做脚本分析，不写听力正确率。

### 恢复已绑定音频

同一路径可被覆盖。派题、作答和复习会核对文件 SHA-256；复习可能仍到期，同时 `audio_ready=false` 并给出 `audio_error`。历史成绩与日期继续可查。音频变更时先恢复与历史指纹一致的原件；没有原件时，核对替代音频与题干、脚本之后，再按用户授权登记与绑定。旧档存在同路径材料指纹时沿用其校验，缺少历史指纹时需显式复核并重绑。哈希用来核对字节一致，语义核对仍由教练完成。

## 阅读

区分选词填空、长篇匹配和仔细阅读。先让学生指出定位依据；讲解正确项与最迷惑的错误项差别，而非只报选项。四级与六级保持不同文本密度和推断深度。微练习不假称完整套卷；完整模拟才按官方题型和时限组织。

## 写作与翻译

写作先核对原题与是否覆盖要求，再按内容、结构、词汇搭配、语法给有原句位置的反馈；优先修改最影响表达的一两处，并让学生重写。翻译先核信息点是否完整和准确，再看句法、搭配与自然度；参考译文不是唯一标准答案。任何数字或等级都标“非官方教练参考”，缺原题或文章不报精确分。用“原句 → 具体问题 → 最小修改 → 同一判据二改”推进。写作优先修题意覆盖或论证关系，翻译优先修漏译、误译或因果关系，再处理词汇。学生交来参考译文或跟着提示重写时，记为辅助练习。不要用高级词替换正确、自然的简单词。

### 二改怎么验收

初稿记录一句原文和一条改稿判据。学生授权留档时，用 `attempt --criterion "一条可观察判据"` 保存判据和证据，记下返回的 `attempt_id`。用户提交对某稿的重写时，用 `attempt --revises 原稿记录ID` 绑定同一题的确切原稿，并自动记为辅助练习。同题多篇独立稿各自记录，不按时间猜重写对应哪篇。只保存反馈与短摘句时省略 `--save-response`。

用 `revisions --item-id ID` 查询稿件关系、判据和反馈，查看 `matches_parent_criterion` 是否有充分记录。旧稿判据若仅存在反馈文字，先核对原文再为本轮显式提供判据。区分可追溯的重写进步和独立写作迁移。验证迁移时，以同一判据闭卷写一道新题，注明对应原句或信息点。

### 翻译的信息点对照

建题时把实际原文放入题面。首次批改先摘出要核对的信息点，例如日期、数量、否定、限定范围、主体和条件。每个点用固定 `key`。写一个 JSON 数组到文件，使用 `attempt --alignment-file FILE.json`，仍按写译要求提交简要反馈和证据。条目示例：

```json
[
  {"key":"开放范围","source_quote":"只在周末延长开放时间","translation_quote":"extends its opening hours every day","status":"distorted"},
  {"key":"入馆预约","source_quote":"入馆无须预约","translation_quote":"do not need a reservation to enter","status":"preserved"}
]
```

状态使用 `preserved`（准确）、`distorted`（失真）、`omitted`（遗漏）、`uncertain`（待核）。遗漏用空值 `translation_quote`。准确性由教练按原译语义逐点核对，引擎检查引文确实存在于当前原文与译稿。尽量选最短可定位的原译片段。重译继续用 `--revises`，沿用同一组 key 与原文摘句，更新译文摘句和判断。读 `revisions` 的 `alignment_delta`，先修新引入的失真或遗漏，再确认原有改进。旧稿只有文字备注时，从原始材料补核后才使用新的结构化对照。

## 词汇与复习

把词放回听读写译语境。先无提示提取，再看释义/例句；用 `attempt` 的 `wrong/partial/correct` 映射 FSRS `Again/Hard/Good`，明确选择 `easy` 才用 `Easy`。引擎保存卡片 JSON 与到期日。FSRS 不可用时按 1、3、7、14、30 天固定间隔，报告标明 `fixed_fallback`。考前到期上限优先于长期调度。
